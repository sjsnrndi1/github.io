# 회원관리 설정

기존 게시글 관리자 화면과 `can_manage_changed_traces()` 권한 함수를 사용합니다. 새 테이블이나 Edge Function은 필요하지 않습니다.

1. 기존 [Gemini 대화 저장 설정](gemini-chat-setup.sql)이 적용되어 있어야 합니다.
2. Supabase SQL Editor에서 [admin-members-setup.sql](admin-members-setup.sql)을 실행합니다. 관리자 조회 함수 3개와 중복 없는 변경 기록을 등록하며 기존 회원·대화는 변경하지 않습니다.
3. 관리자 로그인 후 **회원관리**(`/github.io/admin/members/index.html`)에서 회원 목록과 **대화 보기**를 확인합니다.

## 조회 범위와 개인정보

- DB에서 마스킹한 이름·이메일만 반환합니다. `홍길동`은 `홍*동`, `sjsnrndi1@naver.com`은 `sj***@naver.com`으로 표시합니다. 한 글자 이름은 `*`, 두 글자 이름은 첫 글자만 남깁니다. 미등록 값은 `미등록`입니다.
- 비밀번호, 암호 해시, 인증 토큰, 전화번호, IP, 전체 회원 메타데이터는 조회하지 않습니다. 회원 ID는 대화 조회를 연결하는 내부 식별자로만 사용합니다.
- 마스킹은 일부 정보를 남기므로 완전한 익명화가 아닙니다. **대화 본문은 원문**이며 개인정보를 자동으로 제거하지 않습니다. 첫 질문으로 만든 대화 제목은 목록에 표시하지 않고 날짜로 구분합니다.
- 회원 50명, 대화 30개, 메시지 50개씩 조회합니다. 메시지는 최근 내역부터 가져와 시간순으로 표시하며 이전 메시지를 추가로 불러올 수 있습니다.
- 조회 함수는 서버에서 매번 관리자 권한을 검증합니다. 비로그인·일반 회원은 호출할 수 없으며 기존 회원 본인용 대화 조회 정책은 유지합니다. 회원 수정·삭제 기능은 제공하지 않습니다.

## 적용 후 확인

관리자에서 마스킹과 대화 조회, 일반 회원·비로그인 계정에서 조회 차단을 확인합니다. 다른 회원/대화를 빠르게 선택했을 때 이전 요청의 응답이 섞이지 않는지도 확인합니다. SQL 적용 전에는 설정이 필요하다는 메시지를 표시합니다.

권한 함수는 [Supabase Database Functions 안내](https://supabase.com/docs/guides/database/functions)의 `security definer`, 빈 `search_path`, 명시적 실행 권한 설정 방식을 따릅니다.
