# 바뀐 흔적 관리자 설정

별도 백엔드 서버 없이 브라우저에서 Supabase Auth와 Data API를 사용합니다.
기존 관리자 로그인 화면과 게시글 관리의 폼·목록 구조를 참고했습니다.

## 최초 설정

1. 사이트 회원가입 또는 Supabase Authentication에서 `sjsnrndi12@naver.com` 계정이 있는지 확인합니다. 이메일 인증도 완료합니다.
2. [changed-traces-setup.sql](changed-traces-setup.sql)을 검토합니다. 이 SQL은 지정 계정의 관리자 권한을 변경하고 기존 테이블에 RLS 정책을 설정합니다. 기존 변경 기록은 삭제하지 않습니다.
3. 사용자의 DB 변경 확인을 받은 뒤 Supabase Dashboard의 SQL Editor에서 실행합니다. 프론트의 공개용 키로는 이 관리 설정을 적용할 수 없습니다.
4. `/github.io/admin/admin.html`에서 해당 이메일과 기존 Supabase 계정 비밀번호로 로그인합니다. `sjsnrndi1`이라는 별도 아이디로 인증하지 않습니다.
5. 관리자 메뉴의 **바뀐 흔적**에서 기록을 관리합니다. 등록·수정·삭제는 확인창을 거친 뒤 DB에 반영됩니다.

## 권한 및 검증

- 일반 방문자와 일반 회원은 조회만 허용하고, 관리자는 등록·수정·삭제할 수 있도록 설정합니다. 관리자 여부는 사용자가 변경할 수 없는 `auth.users.raw_app_meta_data`에서 확인합니다.
- 기존 쓰기 허용 정책이 있더라도 새 제한 정책으로 비관리자의 쓰기를 막습니다. 기존에 더 제한적인 정책이 있다면 관리자 쓰기도 막힐 수 있으므로 정책 목록을 확인합니다.
- SQL 적용 전에는 권한 확인 함수가 없으므로 관리자 로그인과 관리 기능이 차단됩니다.
- 로그인 실패, 일반 회원 접근 차단, 관리자 접근, 로그아웃을 확인합니다. 실제 등록·수정·삭제 검증은 사용자 확인 후 수행합니다.
- 사용자 화면은 DB 조회에 성공하면 DB 기록을 기준으로 표시합니다. 조회에 실패할 때만 소스의 `localChangedTraces` 기록을 대신 표시하여 DB로 옮긴 기록의 중복과 삭제 후 재표시를 막습니다.
- `created_user_id`, `updated_user_id`는 로그인 계정 ID를 사용합니다. `created_ip`, `updated_ip`는 DB 트리거가 기록합니다. API 요청의 IP 헤더를 우선 사용하고, 없으면 DB 연결 주소를 사용합니다. SQL Editor의 연결 주소는 브라우저 사용자의 IP와 다를 수 있으며, 둘 다 알 수 없을 때의 `0.0.0.0`은 주소 미확인을 뜻합니다. IP 값은 권한 판단에 사용하지 않습니다.
- **게시글 관리**의 목록·상세·등록·수정·삭제도 기존 `BOARD` 테이블을 사용합니다. [frontend-db-setup.sql](frontend-db-setup.sql)을 SQL Editor에서 실행하면 게시글 쓰기 권한과 첨부파일 저장소가 설정되고, 오늘 변경 기록도 중복 없이 등록됩니다.
- 첨부파일은 `board-attachments` 비공개 버킷에 저장하며 관리자만 내려받습니다. 파일 제한은 10MB입니다. 새 파일을 선택하지 않고 글을 수정하면 기존 첨부파일을 유지합니다.
- 별도 백엔드에 저장되어 있던 게시글과 파일이 있다면 이 SQL로 자동 이관되지 않습니다. 실제 데이터와 저장 위치를 확인한 뒤 별도 이관해야 합니다.
- 다른 글에서 참조하거나 댓글·태그가 연결된 게시글은 기존 외래 키 제약조건에 따라 삭제가 거절될 수 있습니다. 연결 데이터를 임의로 함께 삭제하지 않습니다.
- 공지사항은 관리자 게시글 작성·수정 화면에서 **공지사항** 분류(`notice`)를 선택하여 등록합니다. 사용자 화면 `/github.io/front/notice/index.html`에서는 목록과 상세만 제공합니다. 기존 글을 공지사항으로 노출하려면 관리자에서 해당 글의 분류를 변경합니다. 이 변경의 기록 등록 SQL은 [notice-changes.sql](notice-changes.sql)에 있습니다.

비밀 키, DB 비밀번호 또는 사용자 비밀번호를 프론트 소스와 Git에 저장하지 마세요.

## IP 필수값 오류가 발생한 경우

`created_ip`의 NOT NULL 오류가 발생하면 최신 [frontend-db-setup.sql](frontend-db-setup.sql) 전체를 다시 실행하세요. 변경 기록과 게시글에 IP 자동 기록 트리거를 적용하고, SQL 등록문에도 IP 값을 명시합니다. 파일의 모든 변경은 하나의 트랜잭션으로 처리되므로 `commit` 전에 실패한 작업은 반영되지 않습니다. 같은 날짜·내용의 변경 기록은 중복 등록하지 않습니다.

요청 헤더 조회 방식은 [Supabase API 보안 안내](https://supabase.com/docs/guides/api/securing-your-api)를 참고했습니다. 실제 IP 헤더 전달과 저장 결과는 SQL 적용 후 관리자 화면에서 확인해야 합니다.
