# 바뀐 흔적 관리자 설정

별도 백엔드 서버 없이 브라우저에서 Supabase Auth와 Data API를 사용합니다.
기존 관리자 로그인 화면과 게시글 관리의 폼·목록 구조를 참고했습니다.

## 최초 설정

1. 사이트 회원가입 또는 Supabase Authentication에서 `sjsnrndi12@naver.com` 계정이 있는지 확인합니다. 이메일 인증도 완료합니다.
2. [changed-traces-setup.sql](changed-traces-setup.sql)을 검토합니다. 이 SQL은 지정 계정의 관리자 권한을 변경하고 기존 테이블에 RLS 정책을 설정합니다. 기존 변경 기록은 삭제하지 않습니다.
3. 사용자의 DB 변경 확인을 받은 뒤 Supabase Dashboard의 SQL Editor에서 실행합니다. 프론트의 공개용 키로는 이 관리 설정을 적용할 수 없습니다.
4. `/github.io/admin/admin.html`에서 해당 이메일과 기존 Supabase 계정 비밀번호로 로그인합니다. `sjsnrndi1`이라는 별도 아이디로 인증하지 않습니다.
5. 관리자 메뉴의 **바뀐 흔적**에서 기록을 관리합니다. 등록·수정·삭제는 확인창을 거친 뒤 DB에 반영됩니다.

## 권한 및 검증

- 일반 방문자와 일반 회원은 조회만 허용하고, 관리자는 등록·수정·삭제할 수 있도록 설정합니다. 관리자 여부는 사용자가 변경할 수 없는 `auth.users.raw_app_meta_data`에서 확인합니다.
- 기존 쓰기 허용 정책이 있더라도 새 제한 정책으로 비관리자의 쓰기를 막습니다. 기존에 더 제한적인 정책이 있다면 관리자 쓰기도 막힐 수 있으므로 정책 목록을 확인합니다.
- SQL 적용 전에는 권한 확인 함수가 없으므로 관리자 로그인과 관리 기능이 차단됩니다.
- 로그인 실패, 일반 회원 접근 차단, 관리자 접근, 로그아웃을 확인합니다. 실제 등록·수정·삭제 검증은 사용자 확인 후 수행합니다.
- 사용자 화면은 기존 DB 기록과 소스의 `localChangedTraces` 기록을 함께 표시합니다. 소스 기록을 DB로 자동 복사하지 않습니다.
- `created_user_id`, `updated_user_id`는 로그인 계정 ID를 사용합니다. IP 주소를 임의로 만들지 않습니다. 기존 테이블에서 IP 열이 필수라면 DB의 실제 제약조건을 확인한 뒤 처리 방식을 정해야 합니다.
- 기존 **게시글 관리** 메뉴의 `localhost:8081/posts` 연동은 이번 작업 범위에 포함되지 않습니다. 이번에 Supabase로 전환한 기능은 관리자 인증과 바뀐 흔적 관리입니다.

비밀 키, DB 비밀번호 또는 사용자 비밀번호를 프론트 소스와 Git에 저장하지 마세요.
